Honest limits

  • Status shows only what the evidence contract's project() returns over the unbroken, verified prefix of the chain. After the first break, rejected line or conflict, the board freezes; later envelopes are listed but never projected. A junk line can freeze the board too: that can hide progress, but it never shows a state that didn't happen.
  • Every line is checked for size and structure before anything is hashed. A line over 64 KiB, nesting deeper than 8, a string over 512 characters, broken Unicode or more than 64 entries makes one rejected row that is never hashed. A replay file over 64 MiB, or a live response over 256 lines or 4 MiB, is not read at all.
  • A verified envelope proves the core's key signed it. It does not prove a measurement is physically right.
  • Signatures are checked only against keys pinned in this page; an empty pin list verifies nothing. Until the core serves the pinned key, envelopes show as unverified. TEST KEYS mode uses keys anyone can derive, so only a local server honours it.
  • Colors are chiplet-center temperatures: one number per chiplet. They are not a continuous thermal field. A run whose data has no center temperatures draws its chiplets uncolored: J is the measurement's value and is never spread over the chiplets as if it were one of theirs.
  • The bundled demo is an interface fixture with illustrative numbers. No solver produced them.
  • LIVE means a poll succeeded within 5 s, the verified prefix grew within the last 60 s after the page caught up with the log, it hasn't been cut back, and nothing follows it. Catching up is not progress: the rows a page load reads to reach the end of the log are history, so an idle run shows STALE, not LIVE, until a new row arrives. If a late conflict or break cuts the prefix back, or a refused row arrives after it, the board freezes and LIVE ends at once: STALE · chain broken. LIVE never shows next to a frozen board.
  • A run that /api/view/runs lists as finished shows ENDED · run finished. Integrity problems still win: a frozen board shows STALE · chain broken, and a replaced stream, a row too large or unsupported paging keep their STALE label. A missing or unknown status counts as running. It shows recent progress, never completeness. Duplicates, and envelopes that don't extend the verified prefix, never keep it LIVE.
  • Known limit: a server can withhold any suffix, including a final withdrawal, while it keeps releasing earlier envelopes. LIVE stays on and this page can't tell. Only the full history, replayed later, shows the truth.
  • The live feed reads the run's log by cursor and keeps every row, so a late envelope at a seq already seen still freezes the board. Every page carries a hash of the raw bytes of all rows so far, which the page checks, and the page sends its own hash with each request, so a log replaced under it, even at the same length, shows STALE · stream replaced and stops until you reload. A bad page shows STALE · transport or STALE · paging error and keeps the board as it was. So does a failed /api/view/runs refresh (an error status, no answer, or an answer that isn't a runs list): STALE · transport at once, with the rows and the cursor kept. A row too big to page (413) shows STALE · row too large and stops until you reload. A server without cursor paging shows STALE · paging unsupported and is never LIVE. When the /api/view routes don't answer, the page says so and the replay stays available.

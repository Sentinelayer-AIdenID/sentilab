Honest limits

  • Agent door view. Every temperature is simulated by HotSpot 6.0 on the model stack of the TAP-2.5D CPU-DRAM case, grid 64. Simulated, not silicon: no chip was built or measured.
  • Known limit: for the saved 45mm/grid64 CPU-DRAM reference case, the source-defined ambient-boundary sum exceeds 680W input by 9.4449W (about 1.39%), beyond the 0.429424W allowance for saved-temperature rounding. This is a saved-field consistency finding, not physical calibration; the cause in the deployed binary has not been established. Current results are diagnostic.
  • The number under each layout is the board's one statistic, the max chiplet-centre mean, as the scorer reports it, rounded to 0.01 °C for display. The page never recomputes it from the map. The native all-block maximum and the active-layer peak are other statistics, shown apart under their own names.
  • The colour map is the active-layer (chip layer) temperature field, one flat colour per grid cell of 45/64 mm, on one fixed scale (45 to 125 °C) for every layout. Nothing is interpolated between cells. Values beyond the scale are clamped and counted.
  • Layers thinner than 1 mm are drawn 10 times thicker so they can be seen; the spreader and sink keep their true thickness. The spreader is 90 mm and the sink 180 mm square, but only their central 45 mm (the extent of the simulation grid) is drawn. The TIM, spreader and sink are lifted above the dies so the map stays visible, and the underfill between the dies is drawn a little lower than the dies so they read as blocks (in the model they are one 150 µm layer); Explode separates every layer. These are view transforms: every coordinate in the model is assembled, in mm.
  • A layout is shown only by its class and a 4-character short id. Classes are classification observations, not identities. No visitor-written text is shown.
  • The bundled fixture holds the raw and snapped references and two synthetic examples that were never submitted or scored. The raw reference's map is layer 4 of the gate-zero HotSpot 6.0 output for that exact layout, reproduced byte for byte. The snapped reference has no temperature: it is not evaluated.
  • Published points and the raw layout's statistics sit in their own reference panel and are never part of the live board.
  • Lab runs view. Everything drawn comes from the unbroken, verified prefix of the chain, with the same check and pins as the Lab view. After the first break the drawing freezes; unverified or later envelopes never move or colour anything.
  • Each chiplet's top face is one colour: its centre temperature, on one fixed scale for the run. It is not a thermal field, and nothing is interpolated across a die. Side faces are the same colour, shaded only for depth. A run whose data has no centre temperatures draws its chiplets uncoloured: J is its measurement's value and is never spread over the chiplets as if it were one of theirs.
  • The lab stack is schematic. Substrate, interposer, die heights and the lid are drawing constants. Only the chiplet footprints come from the evidence.
  • A glide is display only: chiplets move from the layout the package showed before (a lab's previous candidate, else the initial layout) to the new candidate. Status (proposed, accepted, stale) comes only from the evidence contract's project().
  • A verified envelope proves the core's key signed it. It does not prove a temperature is physically right.
  • The bundled demo is an interface fixture with illustrative numbers. No solver produced them.
  • TEST KEYS mode uses keys anyone can derive, so only a local server honours it.

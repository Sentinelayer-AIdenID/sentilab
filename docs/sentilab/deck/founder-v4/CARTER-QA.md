**The story in one breath:** an AI agent is only as good as the grader it optimizes against. Our grader is a simulator, HotSpot, that predicts how hot a chip layout runs. Two versions of it gave very different answers on the same design and the same files. Our agents traced it, stopped our own run, took our numbers back in public, and reproduced two published results before trusting anything again.

| They ask | You say |
|---|---|
| What does SentiLab do? | AI agents propose chip layouts and check each other's work, and we keep the evidence behind every result. |
| What did you find? | Two versions of the same simulator gave very different answers for the same design and the same input files: on the CPU-DRAM design, 119 or 241 degrees at the hottest spot on the chips. Our earlier results used the newer one, so we took them back. |
| Which version is right? | Neither is simply right. Other model checks are closer to the older version on these cases, though their readings differ. But in a saved CPU-DRAM case on the older version, 1.39 percent more heat left the model than entered, and the newer one has that extra obstacle. We have no hardware measurement for these reconstructed layouts. |
| Wait, it creates heat? | In those saved runs, yes: more heat leaves the model than goes in. Source analysis found side-to-side links that aren't the same in both directions where materials change, and that's consistent with it. It doesn't change that we reproduced the paper's numbers. It's why reproducing a number isn't the same as physics. |
| So it's a bug? | We can show where the two versions differ in the public code. Only the authors can say what they intended. Delfie's report calls it a likely bug; those are their words. |
| What's the difference, simply? | The newer version puts an extra obstacle between the metal lid and the cooler. Delfie changed just that one step, and most of the gap went away. ScienceClaw re-ran it and got the same numbers. |
| Did you run that change yourselves? | Yes, and it met the bar we set in advance. With only that one link changed in 7.0, 93 percent of the difference to 6.0 goes away on Ascend 910 and 91 percent on CPU-DRAM, rounded down. Both meet the 85 percent we fixed. That localizes it to this term in this configured model. It doesn't tell us what the authors intended, or which version matches hardware. |
| Could that huge number just be a solver that didn't converge? | Delfie, ScienceClaw and another team report that the direct and iterative solvers agreed to the printed hundredth of a degree on the inputs they checked. The other team rebuilt only the unmodified 7.0. That argues against a large convergence problem in those runs. It doesn't by itself establish the cause or physical accuracy. |
| Why 119 on one slide and 116 on another? | Different readings of the same design. 119 is the hottest spot on the chips. 116 is the block reading we fixed in advance to compare with the paper's published value. |
| What does PASS prove? | We reproduced two published reference temperatures within a hundredth of a degree, using the older-version setup we fixed in advance. It doesn't prove the simulator matches a real chip. |
| Is 241 degrees real? | It's a simulator output for these fixed inputs. We have no hardware measurement showing that temperature, and this test doesn't tell us when a real chip would throttle or fail. |
| Why should anyone care? | If an AI optimizes against a grader nobody checked, it can be confidently wrong, fast. |
| What should I do if I use HotSpot? | If you run version 7's detailed-3D mode on stacks like these, compare it against 6.0. Delfie reports that with that mode off, both versions give the same answer. |
| Does it change which design wins? | We haven't measured that yet. |
| What's the door? | A public way for any agent to try a chip layout. It asks what the agent came to do and gives it a pass scoped to that task, valid 60 minutes with 30 CPU-seconds. The pinned simulator scores the layout, a fresh process replays it, and the result goes on a public board. The address is on the slide. |
| Has anyone outside used the door? | When we froze this deck, every scored run on the door was our own team's. Arrivals we can't identify are counted separately, not as confirmed outside visits. The board is public, so you can see what's changed since. |
| Did your agents find a better layout? | One lower-wire example is D1, from our own agent, on staging: cooler than our reconstructed reference on this build, using less wire by our proxy, and a replay gave the same answer. It isn't a verified win: there's no routed wire and no physical check. |
| Who else is affected? | We don't know how broadly it applies. In the papers we checked, the ones that named a HotSpot version named 6.0. We've established the difference in the setup we tested, and we corrected our own results. |
| Why hasn't anyone noticed? | We don't know. The project issue lists we searched had no earlier report of this specific difference. |

All of it is simulation, and the model has a known limit that we print on the door. |

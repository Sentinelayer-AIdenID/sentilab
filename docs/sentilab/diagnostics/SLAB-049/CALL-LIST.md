## Per-call record (astra #56701)

After the run, each retained evaluation directory goes through `python -m sundai_hotspot.slab049 summarize DIR
[--fixture-interposer-mm 45|50 | --slab]`. It reads files only and records:

- **Files.** SHA-256 and size of every generated input and output file, including the **actual**
  `new_hotspot.config`.
- **Precision.** HotSpot prints grid and block temperatures as `%.2f` K; the precision is measured from the files.
- **Package.** Spreader, sink and `r_convec` are read back from the actual config and must match the fixture row.
  A mismatch invalidates the call.
- **Peak.** The layer-4 grid peak and every argmax cell.
- **Chiplets.** Each real chiplet's GRID_CENTER value, with the cell indices and weights used. The centre rule
  averages 1, 2 or 4 cells; the record says which.
- **Chiplet maximum.** The max over those chiplet centre values.
- **TAP's positional stdout selector, recorded separately.**
  - Literal, on this binary's stdout: HotSpot 7 prints no temperatures, so this is recorded as not applicable.
  - Emulated on HotSpot 6.0's stdout layout: every block of every layer is centre-mapped as in TAP's config, plus
    the package nodes. Because it starts from 0.01 K grid cells, it agrees with HotSpot's own centre mapping to
    within 0.01 K.

**Run rules.**

- Every call runs in a fresh, empty directory. The TAP generator skips writing `new_hotspot.config` if one
  already exists (`passive_interposer.py:151`), so a reused directory could run a stale config.
- One solver process at a time (`max_workers=1`).
- No parameter differs between OLD and NEW.
- Nothing is tuned toward any published temperature.

## Pre-declared interpretation (frozen before any run)

Following astra #56701, this stays **non-causal** until the controlled comparison has run. Even then, a result is
"consistent with" a cause; it does not prove one.

### Validity gates

These come first. If any gate fails, stop and report; do not interpret.

- **V1 Identity.**
  - The OLD binary lacks the tag; the NEW binary has it.
  - Every record's package matches its fixture row.
  - Every call ran in a fresh directory, with every input and output hashed.
- **V2 Slab.**
  - Every (a) call's die-centre GRID_CENTER value, in each of the four layers, is within max(0.5% of the predicted
    rise, 0.02 K) of the closed form.
  - NEW's interior drop varies by at most 0.02 K + 0.5% across the three h values.
  - OLD's interior drop follows 52.87, 27.67 and 15.07 K.
  - A failure means the equations or the variant are wrong. (b) and (c) are then not interpreted.
- **V3 Reproduction.** Both OLD reproductions match the committed J64 within 0.01 C, the frozen diagnostic
  tolerance. Otherwise there is identity drift.

### (b) Calibration against the paper, like for like

- **Paper rise.**
  - Ascend 910 original: 75.48 - 45 = **30.48 K**.
  - CPU-DRAM original: 115.94 - 45 = **70.94 K**.
  - **Correction to the brief.** The "about 49.9 C" for CPU-DRAM is the paper's **TAP-optimised** layout
    (94.89 C), not the original. The like-for-like target for the original is 70.94 K. The 2.3 to 2.4 times figure
    compared our best layouts with TAP's optimised one.
- **Metric.** The emulated TAP selector is the paper's own metric. J is reported next to it.
- **First like-for-like OLD ratio.** `rho_old = R_old / R_paper`. If it falls outside [2.0, 2.7] for a layout, the
  2.3 to 2.4 times premise is restated for that layout before anything else.
- **Closure.** `c = (R_old - R_new) / (R_old - R_paper)`, per layout, on the **45 mm** fixture (the paper's setup).
- **Classes.** A class is assigned only when both layouts have 45 mm OLD and NEW, i.e. after Tier B.

| Class | Rule | Wording allowed |
|---|---|---|
| CONSISTENT-MAIN | c in [0.75, 1.25] for both layouts | "consistent with the spreader-sink convection term being the main in-model calibration difference". The residual `R_new - R_paper` is reported with the known remaining differences. |
| PARTIAL | both c in [0.25, 1.25], at least one below 0.75 | "a major contributor; the rest of the gap lies elsewhere" |
| ELSEWHERE | c < 0.25 for both layouts | "the gap lies elsewhere": HotSpot 6 vs 7 lumping, sink-material counting, solver path, stack, geometry, decoding. Claims narrow to "in-model". |
| OVERSHOOT | c > 1.25 for either layout | NEW removes more than the gap. Not read as calibration; the next suspect is HotSpot 6.0's upper-layer rule. |
| MIXED | layouts land in different classes, or the J-based and selector-based classes differ | no class; claims stay "in-model" |

- **Tier A only.** The micro150 original at 50 mm gives an **indicative** `c`, labelled not like-for-like: our
  50 mm fixture against the paper's 45 mm, and the paper itself reports about 2.5 K between 45 and 50 mm on
  Multi-GPU. No class is assigned.
- **Known in-model differences that remain** (ANALYSIS.md section 3 and section 5):
  - interior lumping, half plus half vs upper layer
  - sink material counted 1.5 times
  - SuperLU vs iterative solver
  - layer-0 rule
  - 45 vs 50 mm
  - decoded and rounded centres
  - centre vs max mapping, which the record covers

### (c) Mesh margin and placement dependence for NEW

- **Margin.** Take NEW's max |J32 - J64| on the subset, against OLD's ε (Ascend910 0.16 C, micro150 0.79 C).
  - At or below ε: "the old margin is not contradicted on this subset". This is not a certification; any NEW-based
    headroom or ranking claim needs NEW's own 24-layout mesh study.
  - Above ε: NEW needs that study first.
- **Offset or reorder.** Take `J_new - J_old` at grid 64 per subset layout. OLD comes from the committed mesh J64,
  tied to this host by V3.
  - If the spread across layouts is at most 2ε: the coupling acts as a placement-independent offset on this subset.
  - Otherwise it is placement-dependent and can reorder layouts. That would matter for every OLD headroom result.

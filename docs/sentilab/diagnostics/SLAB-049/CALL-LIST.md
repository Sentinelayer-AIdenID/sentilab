## What changed

**The cause is settled without new solves.** HotSpot 7's detailed-3D model couples layers half and half
(`temperature_grid.c:104`). The sink's `rz` carries the convection term (`:1056`), and `:167` reads it back on
the link. TAP runs `-detailed_3D on` (`passive_interposer.py:205`). The saved grids show the v7 signature:

- spreader 69.6-71.0 K, sink 18.4-18.6 K above ambient;
- a 51.1/51.6 K drop inside the copper;
- `r_convec = 0.009` in all 8 saved configs. That rules out the unscaled-`r_convec` route **for those probes**:
  the generator skips an existing config, so its source alone does not prove it for every run.

These readings are in `ANALYTIC.json` (`committed_run1_signature`), read from files only.

**HotSpot 7 is not patched as the path forward.** In aneta's model, v7 with convection removed from the link
still misses by +3.0 K and +10.8 K.

- The material-only HotSpot 7 flag stays as labelled, bounded diagnostic evidence. It is not the MATCH evaluator.
- The earlier plans (32 calls and 37 executions, then 23 calls) are **not requested** and inherit no grant.

**The MATCH candidate is HotSpot 6.0, the version TAP-2.5D pinned.**

- **Source:** `sundai_hotspot6/` is uvahotspot/HotSpot `a7a3286e368867c26381e0a23e36b3e273bdeda9`.
  - Every file is checked against its upstream git blob (`UPSTREAM_BLOBS.txt`).
  - TAP-2.5D's `util/hotspot` is a 6.0 binary. Its debug-info lines match `a7a3286e`, and it was built
    without SuperLU.
- **Build (x86_64 and aarch64):** `scripts/build_hotspot6.sh` makes two binaries.
  - `hotspot` (kind `hotspot6`): SuperLU, plus a writer-only macro that dumps every layer.
  - `hotspot-tap-faithful`: upstream source, `SUPERLU=0`, as TAP built it.
- **Licence:** the UVA notices are kept (`sundai_hotspot6/LICENSE`, `THIRD_PARTY_NOTICES.md`, and
  `/licenses/HotSpot-6.0-LICENSE` in the image).
- **Identity and selector:** `evaluators.make_oracle(evaluator, purpose)` is the explicit selector.
  - `HotSpot6Oracle` has its own solver version (`HotSpot-6.0:a7a3286e...`) and problem hash.
  - HotSpot 7's class, binary and identity are unchanged.

**Gate zero, in code (`sundai_hotspot/gate_zero.py`).** Search and headroom refuse any evaluator identity until
it has a recorded PASS. The PASS must reproduce the published originals at 45 mm and grid 64, on the
block-centre metric, within the **prospective computational reference-reproduction tolerance of 1.0 K**.

- **Pinned values:** Ascend 910 original 75.48 C and CPU-DRAM original 115.94 C. The out-of-sample TAP points,
  75.47 C and 94.89 C, are pinned as verification cases.
- **Bootstrap:** `reference_validation validate-reference` produces the first receipt and needs no prior PASS.
  `make_oracle` for search and headroom refuses without one. Tests cover both paths.
- **Fresh configs:** every run writes a fresh config, via TAP's own generator into a fresh, empty directory. The
  config is checked byte for byte against the frozen inputs and its hash is recorded.

## The 12 calls

**Reference identity: the legal snapped variant of each 45 mm original.** Raw and snapped are separate reference
identities, and only one fits.

- **Why snapped:** it passes the same constraint checker as every search candidate (margin, halos, 1 mm grid),
  so a later MATCH compares like with like. The raw reconstruction carries the figure's digitizing noise and
  off-grid positions that search can never reach. On Ascend 910 the paper's three layouts differ by only
  0.35 K.
- **Risk, declared now:** if a snapped reference misses by more than 1.0 K, the raw run in the next allocation
  separates snapping from physics before the evaluator is called wrong.

## Per-solve record

Every receipt holds the `solve_record` (`slab049.summarize_evaluation`). Its separately named fields are:

- `active_layer_grid_peak`: layer, peak and every argmax cell, each checked to lie inside the grid;
- `chiplet_centre_mapping`: each chiplet's GRID_CENTER value with its 1, 2 or 4 cells and weights, and the
  maximum;
- `historical_tap_stdout_selector`: TAP's `max(float(stdout.split()[3::2]))`, literal on HotSpot 6.0 stdout, and
  the same metric on the steady file;
- `spreader_sink_hottest_cell_rises`: the spreader and sink rise above ambient at their hottest cells, with the
  v7-signature pattern;
- `config_sha256`, `effective_package` and every input and output hash.

The grid file is parsed strictly (astra #56785). Each layer section must have exactly grid x grid cells, with
in-range indices in order. The parser rejects:

- duplicate layer headers;
- missing layers;
- non-finite or implausible temperatures;
- temperatures below ambient.

## Pre-declared interpretation (frozen before any run)

**Validity first.** If any of these fails, stop and report; do not interpret.

- **Identity:** each binary carries its identity markers. The HotSpot 6.0 evaluator needs its tag and SuperLU;
  HotSpot 7 needs its own markers. Each receipt names the binary that ran.
- **Inputs:** the staged inputs match `SHA256SUMS`, and the config is fresh and hashed.
- **Replays:** each replay's `sample.steady` and `sample.grid.steady` are **byte-identical** to its primary call's.
  A difference means the identity is not deterministic and it fails.

**Gate zero (calls 1 and 3).**

- **PASS:** HotSpot 6.0's block-centre value is within 1.0 K of 75.48 C and of 115.94 C. HotSpot 6.0 then becomes
  the MATCH evaluator. Its receipts unlock `make_oracle("hotspot6", "search" | "headroom")`.
- **FAIL:** MATCH stays blocked. The next allocation runs the raw reconstructions to separate snapping from
  physics.
- **Never** tune h, the sizes, the stack, the grid or the layouts toward 75.48 C, 115.94 C or any published number.

**HotSpot 7 on the same inputs (calls 5 and 7).** Recorded as numerical evidence of the settled cause, together
with its spreader and sink rises. HotSpot 7 is expected to fail gate zero. What happens to the numbers already
produced on HotSpot 7 is an owner decision, not part of this grant.

**Grid 32 against grid 64.** `|J32 - J64|` is recorded per engine and reference as mesh evidence. It does not gate.

## Answers

- WebGL 1 removal: release r163. Migration Guide: "## 162 → r163 / - `WebGLRenderer` no longer supports WebGL 1." (S1, lines 226-228). Deprecation was announced at r153: "WebGL 1 support in `WebGLRenderer` is now deprecated and will be removed in r163." (S1, line 288). r163 release notes, WebGLRenderer section: "Remove WebGL 1 support. #27836, #27853, #27855, #27969 (@Mugen87)" (S2; published 2024-03-29T05:05:47Z). The r187 source still says "WebGL 1 is not supported since `r163`." and throws if it is given a `WebGLRenderingContext` (S3).
- WebGPURenderer fallback: the class doc says that if the browser does not support WebGPU, "`WebGPURenderer` falls backs to a WebGL 2 backend" (S4, lines 21-24). The constructor installs `parameters.getFallback`, which warns "WebGPU is not available, running under WebGL2 backend." and returns `new WebGLBackend( parameters )`. `forceWebGL: true` selects `WebGLBackend` directly (S4, lines 41 and 51-77). `Renderer.init()` calls the fallback when `backend.init()` throws (S5, lines 899-930).
- Entry point: npm `exports["./webgpu"]` = `"./build/three.webgpu.js"` (import specifier `three/webgpu`) (S7). Source entry is `src/Three.WebGPU.js`, which re-exports `WebGPURenderer`, `WebGPUBackend` and `WebGLBackend` (S6). The build file `build/three.webgpu.js` exports `WebGPURenderer` (S7, line 53714). There is also `build/three.webgpu.nodes.js`, whose source `src/Three.WebGPU.Nodes.js` exports `WebGPURenderer` from `./renderers/webgpu/WebGPURenderer.Nodes.js`. `three.webgpu.min.js` does not exist in 0.187.0 (web-01).

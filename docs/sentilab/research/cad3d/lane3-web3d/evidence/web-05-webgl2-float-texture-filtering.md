## Answers

- R32F (and RG32F, RGB32F, RGBA32F) is NOT linearly filterable in core WebGL 2 / OpenGL ES 3.0. It becomes texture-filterable only when `OES_texture_float_linear` is available. S2: "When implemented against OpenGL ES 3.0 or later versions, the existing sized 32-bit floating-point formats become texture-filterable", and "If none of these extensions are supported: floating-point formats with 32-bit per component are not filterable". S1 lists `OES_texture_half_float_linear` as moved to core in WebGL 2.0 "(but not OES_texture_float_linear)".
- R16F (and RG16F, RGB16F, RGBA16F) IS filterable in core WebGL 2 / ES 3.0. S2: "OpenGL ES 3.0 requires that the required floating-point formats with 16-bits per component ('half-float') are filterable". S1: OES_texture_half_float_linear functionality "is core in WebGL 2.0".
- UNVERIFIED by direct table read: the check marks in ES 3.0.6 Table 3.13 ("Texture-filterable" column) did not come out as text. `pdftotext` 4.00, both `-layout` and `-raw` modes, extracts the format names and bit depths but no glyph in the renderable/filterable columns, not even for RGBA8. So the claim about Table 3.13 rests on the Khronos extension text in S2, which describes that table and edits it. The table caption itself was extracted (below).

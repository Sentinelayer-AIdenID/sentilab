## 2. Rendering stack

### 2.1 What the CSP allows (and therefore what any stack must avoid)

| CSP fact | Consequence for 3D | Evidence |
|---|---|---|
| `script-src 'self'`, no `'unsafe-eval'` | Same-origin module files only; no CDN; no library that generates code with `eval`/`Function` | csp.js:7; web-02, web-06 |
| No `'wasm-unsafe-eval'` | No WebAssembly: no Draco/meshopt/KTX2 decoders, no WASM CAD (occt-import-js is WASM), no WASM solver | web-06; cad-05-12 (occt-import-js) |

| No `worker-src`: falls back to `script-src 'self'` | Module Workers from our own files work; `blob:` workers don't | web-06 |
| `img-src 'self' data:` | Textures only from our origin or `data:`; avoid `blob:` image loading (GLTF embedded images) | web-06 |
| `style-src 'self'` | No `<style>` injection, no `style=""`. The 3D page writes styles only per property (`el.style.transform = ...`). CSP3's text gates `cssText` setters and `insertRule` on `'unsafe-eval'`, and per-property writes are outside that set; that last point is a reading of the specs, not a spec sentence, so ACCEPTANCE A-08 checks it in a real browser. | `connect-src 'self'` | `fetch`, `EventSource` only to our origin, i.e. `/api/*` through the Worker | web-06 |

### 2.3 Why our own WebGL2

1. **Trust boundary.** The 3D page verifies Ed25519 signatures in the same realm that draws (pins and key:
   source.mjs:35-72; verification of replays and of every live page: source.mjs:126-133, 156-166).
   Today no verifier page runs third-party code. Our own renderer keeps it that way; every line is reviewed under
   the same rules as scene.mjs.
2. **Size on a 390 px phone.** An estimated 20x or more smaller (gzip) than three.js's WebGL entry, which since
   r186 ships only unminified files (web-01: "Remove minified builds. #33893").
3. **No build step, no exceptions.** The repo has no bundler; three.js addons need an import map that the CSP
   can't host (web-01); three.core.js fails public-names.test.mjs as served (one comment naming a vendor's issue
   tracker; evidence/extra-02). Each workaround (rewrite specifiers, add a narrow test exception, add a pinned
   minifier) is possible, but each is new surface to review.
4. **The geometry is simple.** Every part is an axis-aligned box, a short cylinder or a flat sheet. Instancing
   (WebGL2 core), one clip plane in the shader, RGBA8 textures with NEAREST, and analytic ray/box picking cover
   everything. Section planes are exact rectangles (section 4.5).
5. **Honest look.** Flat, technical shading is what we want (RISKS R-01); PBR, shadows and post-processing, the
   reasons to take a big engine, would push toward photoreal "product CAD".
6. **Testable.** Camera math, picking, explode offsets, section rectangles, texel bytes and instance buffers are
   pure functions with node tests; only GL calls need a browser.

Cost and risk, stated plainly: about 1-2 days to write and review; GL pitfalls (context loss on iOS when
backgrounded, DPR, MSAA, z-fighting between thin layers, transparent-lid sorting) must be handled explicitly.
Mitigations: render-on-demand, rebuild-from-model on context restore, minimum display thickness and polygon
offset, one transparent object drawn last. If schedule wins, Appendix A of PSEUDOCODE.md swaps three.js in behind
the same `render3d.mjs` interface; nothing else changes.

### 2.4 WebGL2 required, WebGPU optional and unused

- WebGL2 is required for the 3D view (core instancing, `texStorage2D`, GLSL ES 3.00). It shipped in Chrome 56,
  Chrome Android 58, Firefox 51 and Safari / iOS Safari 15 (web-09). Requiring it is no stricter than the
  libraries: three.js's WebGLRenderer dropped WebGL 1 in r163 (web-03).
  Without WebGL2, or after a context loss, the page shows the 2D cross-section. Shaders declare their precision
  explicitly; a device that fails to compile them gets the 2D fallback, never a half-drawn scene.
- RGBA8 + NEAREST textures avoid the float-texture filtering question entirely (whether R32F can be linearly
  filtered without `OES_texture_float_linear`: web-05). Nearest is also the honest choice for a coarse solver
  grid (section 5.3).
- WebGPU is not used. Nothing in this design needs compute or more draw throughput, and phone support is uneven:
  Chrome Android 121, Safari / iOS 26, Firefox 141 desktop only and partial, none on Firefox Android (web-09).
  three.js's WebGPURenderer itself falls back to a WebGL 2 backend when WebGPU is missing (web-03), which shows
  WebGL 2 remains the baseline. The optional sketch solver (section 6.3) runs in JavaScript in a module Worker.

## 3. Architecture: one model, three outputs

```
 source.mjs (existing, unchanged)                  parts.json (anatomy lane; static, sha256 pinned)
   verify replay/live -> prefixEnvelopes, K, label        |
            |                                              |
 scene.mjs buildScene/sceneAt (existing)                   |
   footprints, centre temps, J, status, timeline           |
            |                                              |
 field.mjs  fieldRefs(prefix) -> allowlist -> stream.mjs fetch /api/view/artifacts/<sha256>
            checkFieldArtifact (hash, binding, dims, units, bounds) -> verified field + solver layer table
            |                                              |
            +------------------> model.mjs buildModel() <--+
                                  RenderModel (frozen, plain data; provenance tag on every number)
                                       |                 |                    |
                         render3d.mjs (WebGL2)   fallback2d.mjs (SVG)   twin.mjs + scripts (JSON, GLB)
                                       |
 temps.mjs (label rule binding) ----> DOM only: legend, readout, info panel, chips, notice
```

- **The renderer decides nothing.** It draws boxes, instances and sheets with colours already chosen. Every
  piece of meaning (which state, which numbers, which label, which field) is decided by pure modules from the
  verified prefix, exactly as scene.mjs does for 2D today.
- **Text never enters the canvas.** All words and numbers are DOM, produced by our code through `textContent`.
- **Provenance tag on every number** in the model: `evidence` (verified envelope values), `solver` (hash-verified
  solver artifact), `nominal` (parts.json with citation), `schematic` (drawing constant). The info panel prints
  the tag beside each dimension.
- **Same data adapter.** The page imports `../package/source.mjs` (the Package view's one adapter,
  source.mjs:1-12) and the same `reconcile()` (playhead.mjs:1-13), so replay, live, K drops and paging behave
  identically to the reviewed Package view.

## 4. The exploded "open body" view

### 4.1 Levels and the explode control

- parts.json gives each part a `parent` and `stack_order`. Parts with the same parent and order are side by side
  (dies and HBM stacks on the interposer); each order is one **level**. Assembled z: a level starts at the top
  of the tallest part below it.
- Explode amount `t ∈ [0, 1]`: level *k* rises by `t · gap · k`; parts inside an HBM stack (base die + DRAM dies)
  also separate by a smaller inner gap. `gap` is a schematic constant proportional to the model's lateral span.
  The view prints "exploded; spacing not to scale" whenever `t > 0`.
- Controls: a slider (full width on phones) plus Assembled / Exploded buttons; `E` toggles. Tweened 600 ms with
  the existing ease (render.mjs:19); with reduced motion it jumps (package.js:17 already reads the media query).
  Rendering is on demand: frames only while something moves (package.js:235-237 does the same in 2D).

### 4.2 Thickness: true scale vs readable

Real thicknesses span about four orders of magnitude: the solver's microbump layer is 10 µm and its substrate
0.2 mm (passive_interposer.py:144, 147), and a heat sink is centimetres. Default "readable" mode thickens any
layer below a minimum display thickness and shows the chip "thin layers thickened for visibility"; "true scale"
shows real proportions. The info panel always shows true values with their provenance.

### 4.3 Picking, hover, selection

- Picking is analytic and pure: the camera ray (from `mat4` unproject) against every box (slab test) and the
  drawn sites of interconnect arrays. Exact for this geometry, independent of the renderer, testable in node.
- Hover (pointer devices) tints the part; tap or click selects it: the info panel (DOM) shows name, kind,
  material, true dimensions with provenance tags, the solver layer it is lumped into (or "not in the thermal
  model"), and its connections. `Esc` clears.
- A DOM part list mirrors the selection and is the keyboard and screen-reader route to every part.

### 4.4 Labels

- Our own DOM layer, not a library: one absolutely positioned element per label, moved by per-property CSSOM
  writes (`el.style.transform = translate(...)`, never `cssText` or `style=""`; section 2.1), text by
  `textContent`. This is what three.js's CSS2DRenderer does too (CSSOM property writes only: web-04), but that
  addon imports the bare `'three'` specifier (web-01), and ours is about 60 lines.
- A pure culler keeps labels in priority order without overlap: at most 6 on a phone (level names) and 24 on
  desktop (parts), plus the selected part's connections. Leader lines are drawn by the line program.
- Labels never carry temperatures. Temperatures appear only in the legend, the readout and the info panel.

### 4.5 Interconnect highlighting and section planes

- Bump arrays (BGA, C4, microbumps), TSVs and similar are parametric in parts.json (pitch, diameter, height,
  region, count). Each array is one instanced draw of an 8-sided cylinder. Real microbump counts can reach six
  figures, so arrays are sampled on a regular lattice (every *k*-th site), deterministically, within a budget
  (6,000 instances on phones, 60,000 on desktop), and the view says "1 of k² sites drawn; N total (nominal)".
- Selecting a part highlights it, every part in its `connects_to`, and the interconnect between (`via`), and
  dims the rest. RDL is shown as a thin labelled layer; no traces are invented unless the anatomy lane supplies
  routed geometry.
- Section (cutaway): one axis-aligned plane, X or Y, dragged across the package. The shaders discard fragments
  beyond the plane. Because every part is an axis-aligned box, the cut face of each part is an exact rectangle;
  `section.mjs sectionAt()` lists them and the renderer draws them as caps (coloured by material, or by the solver
  field when one is shown on that layer). The **same** rectangles are the no-WebGL 2D fallback, so the two
  can't disagree.

### 4.6 Phone (390 px) and desktop layouts

- Phone: notice; mode chip and run; canvas full width, height `min(56vh, 460px)`; under it one line of legend
  with its label-state chip; then explode slider, segmented controls (Section, Field, Layer), part list, info
  sheet. Labels limited to level names. Lid off by default on phones, as today (package.js:59).
- Desktop: canvas left, info and legend right (the Package view's grid, package.css:102), strip of tracks below.
- One-finger orbit, two-finger pinch and pan; page scroll stays usable outside the canvas.

## 5. Thermal field on 3D

### 5.1 What exists today

No verified envelope carries a temperature field. The live producer's measurements carry `J` (the chip-layer
grid peak), `W`, and the solver's **input** hashes (conductor.py:341-347; test_conductor.py:85). The oracle
reads all 8 grid layers but returns only layer 4 as `heatmap_c` (tap_oracle_worker.py:91-100, 418-431). The
envelope caps (≤ 64 entries per capped field, ≤ 64 KiB per line) mean a grid can never travel inline. So a field
needs: the producer to publish it as an artifact, the API to serve artifacts by hash, and the envelope to point
at it. Until then the 3D view shows geometry, J, and per-chiplet centre colours where they exist, with today's
"not a field" basis.

### 5.2 Proposed binding (smallest change that keeps the trust model)

1. **Artifact** `sentilab-field/0.1` (canonical JSON, written by the core after the solve):
   `{ format, binding: { run_id, measurement, candidate_hash, evaluator_version }, grid: { rows, cols,
   extent_mm, row0 }, unit: "K", layers: [{ index, name, thickness_m, resistivity_mK_W, heat_capacity_J_m3K,
   power, source }], sources: { "samplelayers.lcf": sha256, "new_hotspot.config": sha256,
   "sample.grid.steady": sha256 }, values: [[rows·cols numbers] per layer] }`. The layer table is transcribed
   from the solver's own `.lcf` and config (passive_interposer.py:135-158), whose hashes are already among the
   signed `artifact_hashes`.
2. **Pointer** in the measurement envelope: `values.field = { sha256, format, rows, cols, layers, unit }`. The
   v0.5 input checks already accept it (values is an open object; depth ≤ 8; strings ≤ 512), so no verifier change;
   the contract doc should still name it.
3. **Route** `GET /api/view/artifacts/<sha256>` (read-only, content-addressed, `cache-control: public,
   max-age=31536000, immutable`, ≤ 4 MiB, serves only hashes that some run's log names). The Worker needs no
   change: it passes upstream `cache-control` through (worker.js:34-35).
4. **Authenticity** comes from the signature on the envelope that names the hash; integrity from the hash. The
   view checks, in order and before decoding anything: allowlist (hash named by a measurement `node.create` in
   the verified prefix that `project()` applied), size cap, sha256, strict UTF-8 JSON, format, **binding equals
   the envelope** (run, measurement id, and `evaluator_version` equal to the envelope's
   `semantics.evaluator_version`), dims equal the pointer and caps (≤ 128 × 128 like the oracle's own bound,
   tap_oracle_worker.py:283-287; ≤ 16 layers like scene.mjs BOUNDS.layer), every value finite and inside
   scene.mjs BOUNDS after unit conversion (scene.mjs:84-98). Any failure refuses the whole artifact; the reason is
   listed; nothing is drawn.

### 5.3 Drawing the field

- **Per solver layer, not per anatomy part.** Each of the 8 solver layers becomes one sheet at that layer's
  height, spanning the grid's `extent_mm`, titled with the solver's layer name. Anatomy parts map to a solver
  layer through parts.json `solver_layer`; anything unmapped is labelled "not in the thermal model" while a field
  is shown. The solver's bump layers are homogenised slabs ("underfill with ubump", passive_interposer.py:145,
  147): individual bumps are never coloured as if each were simulated.
- **Texels on the CPU, from the existing colour function.** Once per scale, a 1,024-entry lookup table is built
  by calling scene.mjs `heatColor(t, scale)` (scene.mjs:264-271) at each bin centre; `fieldTexels()` then maps
  every cell through the table into RGBA8 bytes. So the 3D colours, the 2D colours and the legend come from one
  function, and a node test checks the exact bytes the GPU gets. Measured (extra-05): calling `heatColor()` per
  cell costs about 45 ms for 8 × 32 × 32 on a desktop (it re-parses its stops on every call); the table costs a
  few ms to build, maps 8 × 64 × 64 in about 0.2 ms, and stays within 1/255 per channel of `heatColor()`.
- **NEAREST filtering, unlit.** One flat colour per solver cell; no interpolation (V13); the legend states
  "grid R × C, cell w × h mm". The sheet shader is unlit with no tone mapping, so lighting can't make a hot cell
  look cooler; the RGBA8 bytes are written unchanged to the sRGB canvas.
- **Orientation is declared, not assumed.** The artifact says which row is first (`row0`); a test fixture with
  one asymmetric hot cell catches a flip.
- **Why not a float texture with a shader colour map?** It works: upload °C as `R32F` (sampled with NEAREST, so
  no float-filtering extension is needed; linear filtering of `R32F` would need `OES_texture_float_linear`,
  web-05) and map it in the fragment shader against min/max uniforms and a 256 × 1 ramp. The pixels would be the
  same, but the colour function would then exist twice (JavaScript `heatColor()` for the 2D views and legend,
  GLSL for 3D), and the bytes the GPU shows could no longer be checked in node. With the lookup table, colouring
  16 × 128 × 128 cells took about 2 ms on a desktop (extra-05), so one function wins. A shader map becomes worth it only
  for much larger grids or per-frame transient playback, and then it must be tested against `heatColor()` by
  pixel readback.

### 5.4 Scale and legend

- One fixed scale per run over every accepted field value (all layers), rounded out to 5 °C and at least 10 °C
  wide: the rule `runFrame()` already applies to centre temperatures (scene.mjs:226-229). Live runs only widen it
  (playhead.mjs:27-38). Never rescaled per frame.
- The legend shows the bar (`HEAT_STOPS`, scene.mjs:53), ticks from `scaleTicks()` (scene.mjs:277-284), the basis
  ("grid cells, all solver layers, this run"), and the label of the scale itself: `labelForAll()` over every
  identity behind it, because an axis is a derived value (temperature-label.mjs:17-19).

### 5.5 Label states, always visible; never an unlabelled number

- **Which field a layout shows:** the one attached to the measurement that `metricFor()` already picks for that
  layout's J (lab-model.mjs:124; scene.mjs:373-378), the one rule both views share. Two independent states then
  apply, and both are shown:
  - **evidence validity** from `project()`: if that measurement was withdrawn in the evidence graph, or its
    support broke, the field is stale. It is drawn desaturated and tagged STALE with the reason, exactly as the
    2D view treats stale centre colours (render.mjs:8; scene.mjs:355-356);
  - **evaluator label** from the label rule (below). The rule's tag for a withdrawn evaluator is
    "pre-correction", deliberately not "withdrawn", so the two never read as one (temperature-label.mjs:36-37).
- A field's label is `labelFor()` of the **envelope's** evaluator identity, never the artifact's claim (a
  mismatch is refused, so a withdrawn field can't be relabelled as the illustrative fixture).
- Text: every temperature string comes from `temps.mjs formatTemp(valueC, label)`, which throws unless `label`
  is one of the frozen `LABELS` objects (identity check). The DOM unit holds the value and its qualifier in one
  element ("96.8 °C *pre-correction*", title = the rule's full sentence). A static test forbids `toFixed` and
  `°C` anywhere else in the page's modules.
- Pixels: withdrawn sheets carry a screen-space hatch, unvalidated a stipple (shader in PSEUDOCODE section 6), so
  a screenshot cropped to the canvas still shows the state. Illustrative and accepted are plain.
- Chips: the legend's state chip and "Schematic model · not manufacturer CAD" sit inside the canvas wrapper; the
  page notice appears whenever any shown temperature needs it (the rule's `needsNotice`, package.js:280-283).
- Gap to close first: `hasTemperature()` counts only `J` and `center_temps` (temperature-label.mjs:142). It must
  also count `values.field` (with a test), or a field-only measurement would not raise the notice.

## 6. "Real time": honest options

Today's solver is steady state: each evaluation is one completed solve of one layout. The "simulation happening
in real time" is the lab loop itself: a lab proposes, the core solves, the gate decides, and each step is a
signed envelope. That is genuinely live, and it is what the 3D view should animate.

### 6.1 Options compared

| | (a) Replay of completed, verified solves ("frame packs") | (b) Live from the API as the run progresses | (c) In-browser approximate solver |
|---|---|---|---|
| What moves | Playhead over the verified prefix; each measurement's field swaps in at its seq | New verified envelopes every poll; fields swap in when their artifact verifies | A user-dragged layout re-solved locally in a Worker |
| Latency | None beyond fetch (static or cached artifacts) | ≤ 1 s poll interval + page fetch + re-verification of held rows (source.mjs:156-166) + one artifact fetch (8 × 32 × 32: 57 KB raw, 17 KB gzip; 8 × 64 × 64: 60 KB gzip) + parse and texels (8 × 64 × 64 on a desktop: about 4 ms parse, 0.2 ms texels; extra-05); about 1-2 s from signing to pixels (estimate; to measure) | 10-50 ms per edit for a coarse grid in JS (estimate) |
| Cost | Static files; artifacts immutable and cacheable | 1 request/s per viewer to `/api/view/events` (existing), plus one immutable artifact per measurement | Client CPU only |
| Honest label | REPLAY (+ "glide = display only"; any time compression printed, V11) | The existing LIVE / STALE · reason / ENDED rules unchanged; field stamped "as of seq K" | "SKETCH · in-browser approximation · not evidence"; no °C |
| Binding to evidence | The timeline is the verified prefix; artifacts checked by hash against it | Same allowlist, rebuilt on every verification change; K drop removes later fields at once | None, by design: never mixed with verified data, never exported |
| Needs | Artifacts next to the replay (static dir, or `/api/replay/<bundle>/artifacts/<sha256>`) | Producer artifact + `values.field` + artifact route (section 11) | A label decision (below) before any numbers |

"Frame packs" need no new signed file: the playback timeline is the verified prefix (seq → `values.field`), and a
replay bundle is the JSONL plus the artifacts it names. If the producer later adds transient solves, a field
artifact gains a time axis and the view prints "simulated time t; playback × k" (V11). Not today.

### 6.2 Transport for (b)

- **Keep cursor paging as the only data path.** It is the reviewed contract (v0.6.2), already carries replaced-log
  detection (cursor hash, 409) and late-conflict freezing, and the page's poller already backs off and stops on
  terminal states (source.mjs:190-258).
- **Optional SSE doorbell** (needs a new API route): `EventSource('/api/view/doorbell?run_id=…')` whose messages
  only call the poller's existing `poke()` (source.mjs:256). It carries no data, never counts as progress, never
  changes the label; if it fails, polling continues at 1 s. The Worker passes streamed bodies through
  (worker.js:1-2); browsers reconnect EventSource streams by themselves, but stop for good on a non-200 or a wrong
  content type (WHATWG SSE: web-07). Measure edge and Container App idle timeouts before relying on it.
- **WebSocket: no.** The Worker strips `upgrade` and rebuilds the response (worker.js:7, 26, 36); it would need a
  Worker change for no gain over the doorbell.

### 6.3 The sketch solver, if ever built

The task suggests labelling it "illustrative". In our rule, "illustrative" means exactly the bundled fixture and
prints "illustrative · no solver ran" (temperature-label.mjs:24-25, 48-50), which would be false for a solver
that did run. So: dimensionless relative heat only (no °C), its own mode, banner, colour map and legend, never
on the same canvas as verified data, never in the twin. Numbers wait for the label-rule owner to add a state with
tests. It runs in a same-origin module Worker file (no `blob:` worker, no WebAssembly).

### 6.4 Recommended definition

> **Live** means: the 3D view shows each result within seconds of the core signing it, and only under the
> existing LIVE rule (a poll within 5 s, the verified prefix grown within 60 s after catch-up, nothing after the
> prefix). Every field shown is a completed, signed solve, stamped "as of seq K". "Solving" appears only while a
> verified candidate is in `simulation_pending` and the label is LIVE; otherwise "solve status unknown". Live
> never means the solver's intermediate iterates or the chip's own operation.

## 7. Geometry pipeline

### 7.1 Recommended: procedural in the browser from parts.json

- Every part is a box (substrate, interposer, RDL, dies, HBM dies, underfill, TIM, lid, sink), a short cylinder
  (balls, bumps, TSVs) or a sheet. `model.mjs buildModel()` generates them from parts.json, the verified layout,
  and (when present) the verified solver layer table. Two unit meshes (box, 8-sided cylinder) plus per-instance
  transforms cover the whole package.
- Reproducible by construction (pure function of hashed inputs), reviewable (one module, node tests), no binary
  assets, no loader, no decoder, no CSP question.
- Footprints come only from evidence; thickness from the solver layer table when the part maps to a solver layer
  and a verified field artifact is present (provenance `solver`), else nominal from parts.json.

### 7.2 Optional offline CAD (for interchange, not for display)

If the CAD reviewer's lane wants STEP or GLB for engineers or agents:

| Tool | Version (2026-10-31) | License | Role | Evidence |
|---|---|---|---|---|
| build123d | 0.13.0 | Apache-2.0 | `export_step(..., timestamp=)` and `export_gltf(..., binary, linear_deflection, angular_deflection)` | cad-02 |
| CadQuery | 2.8.0 | Apache-2.0 | `Assembly.export(path, "STEP" \| "GLTF" \| "GLB", tolerance, angularTolerance)` | cad-01 |
| OCP | 8.0.1.1 (binds OCCT 8.0.1) | Apache-2.0 | Python bindings both use | cad-03 |
| OCCT | V8_0_1 | LGPL-2.1 + Open CASCADE exception 1.0 | `RWGltf_CafWriter` (GLB, metres, glTF axes, node names from XCAF labels, optional Draco) | cad-04 |
| glTF-Validator (Khronos) | npm `gltf-validator` 2.0.0-dev.3.10 (a pre-release tag; compiled from Dart to JS) | Apache-2.0 | validate any GLB we publish (dev-time tool) | web-10 |
| glTF-Transform | `@gltf-transform/core` 4.5.1 | MIT | can build and write GLB in Node (`Document`, `NodeIO.writeBinary`); not needed if we keep our own small writer | web-10 |

- Pipeline: parts.json → build123d script → `export_step` (fixed `timestamp` for a stable header) and
  `export_gltf(binary=True)`. Both CadQuery and build123d rotate −90° about X for glTF's Y-up and OCCT converts the
  document's mm to metres (cad-01, cad-02, cad-04).
- **Determinism:** OCCT documents a parallel-meshing flag but no determinism guarantee, and build123d meshes with
  it on (cad-02, cad-04). So CAD outputs are checked by **semantic parity**, not byte hash: per-part bounding boxes
  (from OCP) equal `buildModel()`'s boxes within 1 µm, names equal part ids, glTF-Validator 0 errors.
- Licensing: all offline and none GPL, consistent with licenses.html:31. Blender is excluded (GPL: extra-04).
  Nothing from OCCT ships to the site.

The agent twin's own GLB (section 8) does not need CAD at all: a ~150-line deterministic writer emits boxes and
cylinders straight from the RenderModel. That keeps the repo free of npm dependencies; if one is acceptable,
`@gltf-transform/core` (MIT) does the same job in Node (web-10).

## 9. Accessibility and fallback

- **No WebGL2 / context lost:** the 2D layered cross-section (SVG) from the same `sectionAt()` rectangles, the
  part list, legend with label state, and notice. On `webglcontextrestored` the renderer rebuilds every GL object
  from the cached RenderModel and texels; nothing is refetched or re-verified.
- **No WebCrypto (insecure context):** nothing is drawn, as today (package.js:616-620).
- **Reduced motion:** no auto-orbit, explode jumps, playhead steps without glides, no pulses.
- **Keyboard and screen readers:** canvas `role="img"` with a summary `aria-label` (as package.js:407-409 does);
  the part list as buttons; arrows orbit, +/- zoom, E explode, S section, F field, Esc clears; a polite live region
  announces LIVE/STALE changes and new verified results. Label states are words, not colour alone.

# SLAB-006a mesh freeze

Run from the repository root in the requirements.txt virtual environment, after
`make -C sundai_hotspot -j4 SUPERLU=1`. No oracle files are modified by this study.

Freeze **before** running simulations:

```sh
python -m sundai_controller.mesh_study --fixture ascend910 --seed 1 --n 24 --freeze-only
# Commit layouts.json and layouts.sha256 here, before the evaluation command.
python -m sundai_controller.mesh_study --fixture ascend910 --seed 1 --n 24
python -m sundai_controller.mesh_study --check docs/sentilab/evidence/mesh/ascend910/RESULT.json
```

The public PRNG seed is reproducibility metadata. The 384-layout pool contains
unique legal placements generated by descending-area greedy packing with shuffled
grid positions and bounded restarts. Every placement passes Design.check and the
oracle's margin, microbump-halo and placement-grid checks. Of this pool, the eight
smallest mean pairwise Euclidean center distances are called clustered, the eight
largest spread, and eight random layouts are sampled from the remaining pool.
These categories are relative geometric strata, not thermal optimization labels.
Chiplet identity and power assignment are fixed. Layout selection never evaluates
J. The 0.01 C diagnostic tolerance is also frozen before evaluation.

The harness reads the frozen file, verifies its SHA-256 and geometry/config
contract, and refuses to overwrite it or existing results. Each grid has a fresh
oracle and records its problem, source and binary hashes; workers are closed even
if evaluation fails. J is the chip-layer grid peak in Celsius. All-layer peaks are
also recorded for comparison, but do not enter e. Timing includes oracle overhead;
solver-only and total study times are recorded separately.

On POSIX, new runs record process CPU plus reaped worker/solver child CPU with
`getrusage` differences, sampled after all workers close. Run the CLI in a
dedicated process without concurrent child work. No warm-up solver runs are
performed by this harness; every successful oracle call executes the solver
once. This is per-run accounting, not a shared enforcement ledger. Failed runs
do not produce a completed RESULT.json and require external accounting.

The shared reservation is **150 solver executions and 6 CPU-minutes across both
fixtures**, including warm-up and validation. The committed Ascend910 run
predates that instruction; its CPU fields are null, not zero or elapsed-time
estimates. Known study/validation runs account for at least 102 executions,
with other gate executions unaccounted for. Further reproduction or micro150
runs require reconciled accounting or a revised remaining allowance.

The mandatory rule compares signs on reference gaps strictly greater than 2e
(2e16 for grid 16). Exact coarse ties count as violations; gaps equal to the
threshold are excluded (a 1e-12 C guard absorbs binary roundoff at decimal boundaries). The same-sample max-error bound mathematically guarantees
zero violations, so eligible/excluded pair counts and fixed-0.01 C diagnostics
must accompany any interpretation. The fixed tolerance excludes small reference
gaps; it does not round coarse values or make approximate ties transitive.

Each comparison also reports the largest reference-grid gap that the coarse
grid reverses or leaves tied, considering all unequal reference pairs. For this
Ascend910 set it is 0.11 C at grid 32 and 0.39 C at grid 16. These are observed
reference gaps, not guaranteed thresholds on coarse-grid differences.

For independent reruns of three frozen layouts:

```sh
python -m sundai_controller.mesh_study --fixture ascend910 --seed 1 --n 24 \
  --grids 32 64 --layout-ids clustered-01 spread-01 random-01 \
  --output-dir /tmp/mesh-three-layout-proof
```

Compare each J by layout id and grid with the committed RESULT.json; subset error
summaries are recalculated for the subset. Rebuild binary hashes may differ across
compilers; source/config contracts and J values should be compared explicitly.
For a small real smoke study, freeze n=4 to a scratch layouts path, then run that
path with `--n 4 --grids 16 32` (its reference is 32, and e/e16 are null).

To test the checker, copy RESULT.json, alter a J32 to reverse a well-separated
J64 pair, leaving the recorded tolerances and summary intact, then run `--check`
on the copy. It exits 1 on summary mismatch or inversion at the published 2e
threshold. It validates arithmetic consistency, not cryptographic authenticity;
coordinated edits of values and summaries require independent oracle reruns.

`--fixture micro150` deliberately errors until SLAB-002b wires that oracle fixture.
The same generator/evaluator consumes the fixture's geometry and powers through
one factory; it must never silently run Ascend910 under the micro150 label.
Micro150 measurements are a follow-up after claude-warden announces the wiring.

## Memory interface

```python
from sentilab_core.memory import MemoryStore
store = MemoryStore(memory_dir, ledger_root=tenant_ledger_dir,
                    public_keys=trusted_public_keys, tenant="tenant-a",
                    held_out_families=["evaluation-a"])
scope = dict(tenant="tenant-a", run="memory-drill", arm="baseline",
             family="training-a", seed=17)
store.write(scope, {"id": "finding-1", "text": "A fixture finding"}, ["measurement-a"])
store.recall(scope, "finding")
store.invalidate(scope)  # current invalid evidence, without changing the log
store.audit(scope)       # original writes, including invalidated memories
```

Every field is required. The nonnegative integer seed is type checked (booleans
and floats are refused). The canonical typed tuple is hashed into the storage
key, and the original scope is verified on read. IDs are unique **within** a
scope; repeating identical content is idempotent. Query is a case-insensitive
literal substring over the canonical JSON item, in stable append order.

The trusted host binds one tenant to its ledger root and held-out policy. Provision
a separate ledger root per tenant: the PR #15 envelope has no tenant field.
A caller's scope cannot change that host tenant. This local interface does not
implement tenant authentication; a future service must bind Context from its
principal, never from a request. CLI/MCP expose recall and audit only; writes are
an in-process host API and refuse held-out families before creating the store.

Each write requires nonempty, currently valid evidence references. All listed
references must remain valid; OR-of-AND alternative supports are evaluated by the
ledger projection. Recall replays the current authenticated ledger and uses its
projected validity, not cached statuses. A withdrawal removes direct and stale
transitive memories. Independent support survives. A withdrawal retraction can
restore recall. Nothing rewrites or deletes the audit log.

Writes carry a ledger sequence/hash anchor. A broken chain or replaced signed
history prevents recall and further writes, while the original audit remains
readable. Memory rows form a hash chain with an fsynced durable head and per-scope
file locking. The filesystem is trusted host storage; this is not a remotely
signed or adversary-proof memory store. Recall is a snapshot, not an acceptance
decision or a lock on subsequent ledger updates.

Runtime validity inherits PR #15's Python projection and supported event subset;
unsupported events fail closed. General contract validation remains that
projection's responsibility. The correction fixture additionally checks its
Python projection against the reviewed JavaScript contract before/after withdraw.

## Advisory routing interface

`AdvisoryRouter(registry, calibration_examples, threshold=0.75).route(task)` takes
an explicit deterministic adapter proposal, for example
`{"candidate":"thermal-lab","score":0.9}`. It does not infer a task from prose,
call a model, launch a capability, grant permissions, or decide acceptance.
Unknown routes reject even at score zero. Registered routes without fitting
support abstain. Confidence below the threshold abstains; equality may suggest.

Confidence is empirical candidate correctness fitted separately for each route
and score bucket: `[0,.25)`, `[.25,.5)`, `[.5,.75)`, `[.75,1]`. Raw score and
calibration sample count are returned alongside confidence. `calibrate(heldout)`
only evaluates; it does not refit. Fitting and held-out IDs **and families** must
be disjoint. Their declared provenance is supplied by the fixture owner.

The frozen example has 9 fitting and 8 held-out examples: candidate accuracy
6/8, 3/8 abstentions, 5 suggestions with 4/5 selective accuracy, and 5/8 decision
accuracy (including correct abstentions). `RESULT.json` includes all predictions
and confidence-bucket counts/accuracy. These small synthetic numbers establish
interface behavior and are not a claim about deployment calibration.

## CLI and MCP

Configure the host (paths are local; the fixture path is not a tool argument):

```sh
export SENTILAB_LIVE_DIR=/path/to/tenant-ledger
export SENTILAB_MEMORY_TENANT=tenant-a
export SENTILAB_MEMORY_HELD_OUT='["evaluation-a"]'
export SENTILAB_ROUTING_FIXTURE=docs/sentilab/evidence/SLAB-010/routing-fixtures.json
python -m sentilab_cli memory recall --scope '{"tenant":"tenant-a","run":"memory-drill","arm":"baseline","family":"training-a","seed":17}' --query finding
python -m sentilab_cli memory audit --scope '{"tenant":"tenant-a","run":"memory-drill","arm":"baseline","family":"training-a","seed":17}'
python -m sentilab_cli route --task '{"candidate":"thermal-lab","score":0.9}'
python -m sentilab_cli route --calibrate
```

The existing public-key registry/`SENTILAB_VIEW_PUBLIC_KEYS` config verifies the
ledger; no signer is needed for these operations. MCP names are
`sentilab_memory_recall`, `sentilab_memory_audit`, `sentilab_route`. Arguments match
the shared Python operations (`scope`, optional `query`; or `task` exclusively
with `calibrate: true`). The stdio host advertises their schemas. Tests execute
both real CLI and MCP processes and compare receipts after a withdrawal, for
advice/abstention/calibration, and for rejection of unknown routes and tenants.

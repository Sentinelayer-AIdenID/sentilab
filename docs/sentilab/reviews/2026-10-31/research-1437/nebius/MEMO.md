## Constraints that matter

**Storage is not an immutable evidence service by itself.** Nebius explicitly does **not** support S3 Object Lock/Legal Hold, object ACLs or S3 event notifications. ETags are not guaranteed MD5; filesystem buckets do not support integrity checksums and have weaker conditional-write behavior. Choose a regular versioned bucket, keep our original SHA256 manifests and primary copies, use explicit upload/download receipts and bucket policies, and avoid automatic deletion during this first handoff. Versioning plus permissions is not WORM retention. Keep HTTPS; it is the service default. [Compatibility](https://docs.nebius.com/object-storage/interfaces/s3-api-compatibility.md), [HTTPS behavior](https://docs.nebius.com/object-storage/http-access.md).

**Our LoRA is not automatically deployable to Token Factory.** Public serverless endpoints offer base models; dedicated endpoints offer custom weights for eligible models. The more specific [custom-weights page](https://docs.tokenfactory.nebius.com/ai-models-inference/dedicated-endpoints/custom-weights.md) says this feature is beta, available on request, with supported configurations/onboarding varying. We have no evidence that this account or our exact Qwen3-4B/PEFT adapter is admitted. A normal cloud VM is a separate route with more runtime control, not evidence that the managed endpoint accepts our checkpoint. [Dedicated comparison](https://docs.tokenfactory.nebius.com/ai-models-inference/dedicated-endpoints/overview.md).

**ARM64 and CUDA need separate checks.** The captured VM catalog names Intel/AMD host CPUs; it does not document attaching our external GB10 as managed Nebius capacity. Our retained failure log names an `aarch64` native extension. Therefore a listed x86 VM needs a matching `linux/amd64` image/native dependency build; a multi-architecture tag must be resolved to the actual platform digest. Model tensors and Python source are candidates for reuse, while Triton/FlashInfer/CUDA compiled caches are target-specific. Nebius recommends stable `ubuntu24.04-cuda13.0` for the listed GPU platforms; it fixes CUDA 13.0 and driver 580.x. CUDA 12.8/570.x is an alternative only for specified platforms; B200's single-GPU preset explicitly requires 580.x or newer. These are published platform rules, not compatibility tests of our vLLM build. [Catalog](https://docs.nebius.com/compute/virtual-machines/types.md), [boot images](https://docs.nebius.com/compute/storage/boot-disk-images.md).

**Choose model IDs from current operator evidence.** The [November 2026 notice](https://docs.tokenfactory.nebius.com/model-deprecations-november-2026.md) removes named serverless models on November 9 and says requests are not automatically rerouted. A documentation quickstart model string is not a current entitlement probe or a frozen scientific version. Preserve exact provider/model response identity, request/response hashes and measured usage before admitting a route.

## Concrete admission prerequisites

1. **Archive:** Warden confirms project/payer, region, private regular bucket and minimal upload/read permissions through secure credentials; root freezes the exact permitted files, model/license attribution and retention policy. Use a reviewed one-shot transfer with SHA256 download verification, byte counts and billing dimensions. Keep PC and GB10 originals until independent handoff acceptance.
2. **Hosted API:** Warden supplies the secure entitlement and actual current model/price/payer; root binds it to the shared admission, request limits, STOP/cancellation, cost reservation and CLI/MCP contract. First proof is a separately authorized non-scientific connectivity/schema fixture. Scientific prompts remain behind existing headroom/eligibility gates.
3. **Cloud compute or custom weights:** verify target CPU/GPU architecture, exact image/driver/CUDA/vLLM/PEFT compatibility, memory and executable scratch needs. Require an independent source review, explicit new run identity/debit/deadline, bounded fixture requests, complete failure/cleanup receipts and teardown accounting. Managed custom weights additionally need Nebius's beta enablement and exact model-format acceptance.

Published billing differs by service: [Token Factory](https://docs.tokenfactory.nebius.com/ai-models-inference/dedicated-endpoints/overview.md) describes serverless per-token pricing and dedicated per-GPU/hour pricing with per-minute granularity. [Object Storage](https://docs.nebius.com/object-storage/resources/pricing.md) lists Standard storage at USD0.0147 per GiB per730 hours, before applicable taxes, plus request/egress charges. These are documentation terms, **not an account quote, SentiLab estimate or current bill**. No Nebius service call, credential lookup, account creation, upload, rental or scientific job occurred in this review.
